# internal/arch/sync_writes.txt: the machine-readable form of docs/design/01 §6.3
# (closed list of synchronous, same-transaction cross-module writes; 05 §2.4-3,
# 06 H-2). Format: <caller> -> <provider>.<Interface>.<Method>; * = every module.
# TestSyncWritesAreAllowed reads it as the allow-list for "// sync-write:" ports.
#
# Written once by BE-004; module tickets never edit this file (BE-001 R9). A new
# line needs 01 §6.3 first (orchestrator). On a conflict with 05 §2.4, 01 wins.

# Every module: audit log and file attachment in the caller's transaction.
*         -> audit.Logger.Log
*         -> files.Files.Attach

# Consent records (01 §6.3 "Ek senkron yazmalar"). 05 §2.4 allowed "*" here;
# 01 names three callers, and 01 wins (06 H-2, H-11).
identity  -> consent.Recorder.Record
students  -> consent.Recorder.Record
events    -> consent.Recorder.Record

# Targeted post publication (feed) and dispatch quota (outreach).
feed      -> entitlements.Entitlements.Consume
feed      -> outreach.Targeting.ScheduleDispatch
outreach  -> entitlements.Entitlements.Consume

# Contact request and its acceptance (messaging).
messaging -> entitlements.Entitlements.Consume
messaging -> students.AccessGrants.Grant

# Club claim approval grants club_admin (directory).
directory -> orgs.OrgAdmin.GrantRole

# Order placement (orders).
orders    -> catalog.Offerings.Reserve
orders    -> entitlements.Entitlements.Grant

# Transfer match = payment capture (payments) and payout paid (ledger).
payments  -> orders.Orders.ApplyPayment
payments  -> ledger.Poster.Post
ledger    -> orders.Orders.MarkLinesPaidOut

# --- Pending rationale in 01 §6.3 (06 H-2): the named ticket writes it into 01,
# --- or deletes the line.
# T-78: directory opens the club/university org in its own transaction; BE-020.
directory -> orgs.OrgAdmin.Create
# 05 §2.4 "derived" lines (01 §4.18, §7 orders.expire_unpaid); BE-040 (06 H-2,
# rationale for 01 §6.3 in the BE-040 ticket's doc patch): a full payment
# activates the pending rights of the order in the capture transaction (01 §6.3
# "Havale eşleştirme": orders.ApplyPayment → ActivateBySource); an unpaid order
# that expires or is cancelled gives its units back and revokes its pending
# rights in the transaction that ends it, so stock and rights never outlive the
# order nor the order its stock. 05 named the revocation "Release"
# (entitlements' Release reverses a usage); the entitlements method is
# RevokeBySource.
orders    -> entitlements.Entitlements.ActivateBySource
orders    -> entitlements.Entitlements.RevokeBySource
orders    -> catalog.Offerings.Release

# BE-032 (rationale for 01 §6.3 in the BE-032 ticket's doc patch): the reverse of
# "Hedefli gönderi yayını" — deleting a company's targeted draft, or a moderator
# rejecting it in review, gives its targeted_post unit back in the same transaction
# (04 §2.7 deletePost "+ hak iadesi"; DECISIONS-LOG 2026-10-03), so a unit is never
# lost by a crash between the delete and the release nor released for a post that
# stays.
feed      -> entitlements.Entitlements.Release

# 06 H-49 (T-193; BE-049 writes this line, rationale for 01 §6.3 in the BE-049
# ticket's doc patch): kvkk deletes a data export file in the transaction that
# clears the request's export_file_id (7-day purge, account erasure), so the
# file never outlives its reference nor the reference its file.
kvkk      -> files.Files.Delete

# BE-057 (06 H-49 pattern; T-193, T-221, T-239, T-247; rationale for 01 §6.3 in
# the BE-057 ticket's doc patch): the owning module deletes a file in the
# transaction that clears its reference, so the file never outlives its
# reference nor the reference its file (the objects go after the commit).
# identity: student documents (erasure, file.rejected, edu_document retention);
# directory: club claim evidence (erasure, file.rejected, club_claim retention);
# students: replaced/deleted avatars and CVs (profile edits, erasure, file.rejected);
# feed: media of deleted drafts, replaced images and purged removed posts (port
# with the feed sweepers after BE-032).
identity  -> files.Files.Delete
directory -> files.Files.Delete
students  -> files.Files.Delete
feed      -> files.Files.Delete

# BE-050 (01 §6.3 already names it: "events.purge_exports için events → files.Files.Delete", T-193,
# 06 H-49): events deletes a registration export file in the transaction that clears the export's
# file_id (the 7-day purge; a build that lost its row), so the attendees' file never outlives its
# reference nor the reference its file (the objects go after the commit).
events    -> files.Files.Delete

# BE-041 (06 H-56, T-18, T-227; BE-040's doc patch, rationale for 01 §6.3 in the BE-041 ticket's doc
# patch): the model C twin of "Havale eşleştirme". A finance admin's confirmation that the buyer paid the
# payees directly records the direct_confirmed payment and pays the order (its rights active, its splits
# written) in one transaction, so a confirmation never exists without its paid order nor a paid order
# without the confirmation that paid it.
payments  -> orders.Orders.ConfirmDirectPayment

# BE-035 (rationale for 01 §6.3 in the BE-035 ticket's doc patch; the twin of 06 H-64): a dispatch's
# targeted_dispatch unit goes back in the transaction that ends the dispatch without sending
# (cancelDispatch, a post that left the feed before the run, an audience below 10), so a unit is never lost
# by a crash between the two nor released for a dispatch that ran. A targeted post that leaves before it
# was ever published (draft deleted, rejected in review) withdraws its dispatch in its own transaction: the
# unit goes back and the dispatch row goes before the post row (the composite FK of 06 H-38).
outreach  -> entitlements.Entitlements.Release
feed      -> outreach.Targeting.DiscardDispatch

# BE-043 (orchestrator note 2026-10-14; rationale for 01 §6.3 in the BE-043 ticket's doc patch): "İade tamamlama".
# Completing a refund after its EFT records it on the order (the order's and the line's refunded amounts, the
# partially_refunded / refunded status, the rights of a fully refunded line revoked) in the transaction that completes
# the refund, raises the payment's refunded amount, posts refund_completed and writes payment.refunded, so money that
# left Koro's account is never missing from the order nor an order refunded without its ledger entry.
payments  -> orders.Orders.ApplyRefund

# BE-068: refund completion and manual receivable collection take the ledger's
# transaction-scoped payee lock before order/line locks. It coordinates payout
# snapshots, refunds and receipt reservations; this port changes no persistent
# row and shares the caller's transaction (ticket DocPatch, 01 §6.3).
payments  -> ledger.LedgerLines.LockPayees
